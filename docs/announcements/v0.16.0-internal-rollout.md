## ayx v0.16.0 is ready for internal evaluation

We are preparing `ayx` v0.16.0 for internal rollout. This release makes the
new Wizard authentication orchestration the default for `ayx one login` while
keeping the legacy email-OTP adapter available as an explicit rollback path.

The Alteryx One surface has also been re-verified across authentication,
identity, workspaces, plans, scheduling, connections, datasets, jobs,
workflows, and reversible CRUD probes. Remaining OpenAPI coverage gaps are
documented roadmap items rather than hidden failures.

### What to try

- Install the v0.16.0 artifact from the GitHub release page.
- Configure the regional host for the workspace, for example
  `https://<region>.alteryxcloud.com`; the region is workspace-specific.
- Run `ayx one login` with secure keyring persistence when available.
- Use `--secret-policy session` for a non-persistent evaluation, or choose the
  explicit plaintext fallback only when the environment cannot use a secure
  store.

### Rollback

If authentication behaves unexpectedly, set `AYX_AUTH_ROLLOUT=legacy` and
retry. Please include the command, platform, region, redacted error envelope,
and rollout setting in feedback. Do not share OTPs, passwords, access tokens,
profile files, or keyring exports.

The `canary` rollout is reserved for isolated validation and should not be
used as a general user setting. Legacy decommissioning is not part of this
release; it requires a later canary, soak, telemetry, and rollback review.

### Platform note

The release workflow publishes macOS artifacts with an explicit unsigned
warning when Apple signing/notarization credentials are unavailable. Windows
and Linux artifacts remain the primary immediately installable paths in that
case.

Please report issues through the repository issue tracker or the internal
ayx support channel, including the redacted diagnostics described above.
