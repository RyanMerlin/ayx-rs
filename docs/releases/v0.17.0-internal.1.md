# AYX-RS v0.17.0-internal.1

Internal Windows and WSL2/Linux evaluation release.

This release makes the Wizard email-OTP authentication flow the default for
`ayx one login`. The Legacy email-OTP flow remains available as an explicit
rollback path:

```text
ayx one login --auth-flow legacy
```

The equivalent environment override remains available for automation:
`AYX_AUTH_ROLLOUT=legacy`.

## First-time setup

1. Extract the platform artifact, put the included `ayx`/`ayx.exe` on your PATH, and run `ayx onboard`.
2. Paste the Alteryx One workspace URL when prompted.
3. Choose **Log in now**.
4. Enter the emailed one-time passcode and workspace password.
5. Verify the connection:

   ```text
   ayx one auth status
   ayx one workspace current
   ```

Credentials use the operating-system secure store by default. Use
`--secret-policy session` for a temporary or constrained environment. Plaintext
profile storage is an explicit fallback and should not be used for ordinary
internal workspaces.

## Recovery

Do not automatically retry a login when the CLI says an OTP send or PAT mint
may have committed. Preserve the profile and inspect the redacted error. If a
fresh login is required, use the independently characterized Legacy flow:

```text
ayx one login --auth-flow legacy
```

Do not send OTPs, passwords, tokens, profile files, or keyring exports with a
support report. Include the version, operating system, command, rollout
selection, and redacted error text instead.

## Platform scope

This internal release is a target-platform evaluation build for native Windows
and WSL2/Linux. Disposable-tenant live authentication and native keyring
signoff are required before broad internal distribution. Apple/macOS validation
and distribution are deferred.
