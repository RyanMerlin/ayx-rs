# AYX-RS v0.19.2

This release strengthens Alteryx One authentication and makes One command
output suitable for live demonstrations and everyday terminal use.

## Durable Alteryx One OAuth API-token sign-in

`ayx one login --oauth-api-token` is a guided, explicitly non-OTP setup path
for an OAuth 2.0 API token generated in Alteryx One. It asks for the public
client ID and hides the refresh-token entry. The CLI verifies the pair before
persisting it in the operating-system credential store. Access tokens are
renewed from that refresh credential when needed; neither token is written to
the profile or normal command output.

An ordinary `ayx one login` retains an existing OAuth API-token credential
instead of spending a refresh grant. Use the explicit API-token mode only to
set up or replace that credential.

## Clearer One output

Default terminal output and compact JSON now project the underlying resource
rather than transport timing, retry, and raw-response metadata. `--output
json-full` remains the deliberate diagnostic format for that full transport
envelope.

Workspace people and admin lists now correctly read the service's nested list
wrapper and show useful identifiers, including email when present. Unknown
list wrappers report an actionable compatibility cue instead of falsely
claiming there are no items.

## Agent Studio assets

Adds the documented `one agent-assets` command family for bounded Agent Studio
asset discovery and registration workflows. Mutating operations continue to
use the standard dry-run and confirmation protections.

## Validation

The release is gated by formatting, generated command-surface validation,
workspace clippy, locked workspace tests, a release build, and the published
cross-platform tag workflow. Live Alteryx One checks confirmed secure OAuth
authentication plus workspace, people, and admin reads.
