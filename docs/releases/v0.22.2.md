# AYX-RS v0.22.2

Patch release for production administration correctness and operator safety.

## Highlights

- `ayx one person delete` remains a stable global-person deletion command. It
  is dry-run-first and requires `--apply` plus confirmation. If the provider
  temporarily disables its endpoint, the CLI reports `gone` and does not
  substitute the semantically different workspace-member removal operation.
- Agent Studio private-preview endpoints now consistently return the typed,
  non-retryable `capability_unavailable` outcome when no existing browser
  session is available. The CLI does not import cookies or automate browser
  authentication.
- Schedule creation honors explicit `--enabled`/`--disabled` intent, verifies
  the effective provider state, and includes the created schedule ID and
  creation evidence in incomplete reconciliation outcomes.
- Job Library help and workflow-run envelopes make the distinction between Job
  Library entries and cloud-native workflow executions explicit. External
  outputs remain governed by their backing storage retention policies.

## Validation

This patch is gated by formatting, generated command-surface verification,
locked release builds, and the release workflow’s cross-platform test,
packaging, SBOM, checksum, and provenance steps.
